**สถานะงาน:** ตรวจและจัดทำรายงานเท่านั้น ยังไม่แก้โค้ด รูปภาพ ข้อความ หรือ JSON ที่เว็บใช้งาน  
**ต้นฉบับหลัก:** https://hi.matsuda-sangyothailand.com/ โดยเน้นหน้า Related Links ที่ผู้ใช้ระบุ  
**ฝั่งเว็บใหม่:** ตรวจไฟล์ repository ใน `data/legacy/`, `data/locales/`, `data/assets.json` และคอมโพเนนต์ที่ใช้แสดงจริง ไม่ใช่การรับรองพรีวิวหรือ deployment ภายนอก

## 1. อ่านข้อจำกัดนี้ก่อนใช้รายงาน

รายงานนี้ **ครอบคลุมรายการเว็บใหม่ครบ 28 หน้า แต่ยังไม่ใช่การรับรองว่าตรวจต้นฉบับ live ครบ 28 หน้าในแต่ละภาษาแล้ว**

- **A — 7 หน้า:** อ่าน live ได้เป็นภาษาอังกฤษ จึงเทียบข้อความที่เครื่องมืออ่านได้ ชื่อไฟล์รูป และลิงก์กับข้อมูลโปรเจกต์ได้
- **B — 21 หน้า:** ตรวจข้อมูลจริงใน JSON ของไทย/ญี่ปุ่น/จีนแล้ว แต่ยังยืนยันต้นฉบับ live ของภาษานั้นไม่ได้ ต้องไม่ถือว่าความต่างจาก ENG เป็นข้อผิดพลาดการแปลโดยอัตโนมัติ
- ลอง `management.php?lang=th`, `?lang=jp`, `?lang=cn`, `?language=th` และ `index.php?lang=th` แล้ว เครื่องมือยังได้รับข้อความอังกฤษเดิม; `management_jp.php` ตอบหน้า 404 จึง **ไม่ใช้ URL ที่เดาขึ้นเป็นหลักฐานภาษาญี่ปุ่น**
- รายการ URL live ในตารางเป็น **หน้าอ้างอิงแบบ default ภาษาอังกฤษ** ไม่ใช่การอ้างว่ามี URL live ของทุกภาษาตามนั้น ต้องยืนยันกลไกเปลี่ยนภาษาของเว็บเดิม (session/cookie/ลิงก์จริง) ก่อน
- ผลอ่าน live ไม่ใช่ DOM screenshot: สิ่งที่ไม่ปรากฏในผลอ่านอาจเป็นส่วนที่เครื่องมือไม่ดึง เช่น footer ที่ซ่อนบางส่วน/iframe จึงไม่สรุปว่าไม่มีในต้นฉบับ
- เทียบภาพด้วย **ชื่อไฟล์และการอ้างอิง** ไม่ได้ดาวน์โหลดไบต์ live มาเทียบ checksum; checksum ที่รายงานในหัวข้อนโยบายเป็นการเทียบไฟล์ local สองไฟล์เท่านั้น
- หน้ารางวัลมี pagination 11 หน้าตาม live ENG แต่รอบนี้ตรวจรายละเอียดหน้าแรกได้เท่านั้น หน้า 2–11 ยังไม่สำรวจครบ ไม่ระบุจำนวนเอกสารที่ขาดแบบคาดเดา
- ไม่มีการทดสอบส่งฟอร์มจริง ไม่มีการตรวจอายุใบรับรองทางกฎหมาย และยังไม่ได้ตรวจรับคำแปลโดยเจ้าของภาษา

2. **สำรวจรางวัลให้ครบ:** เปิด pagination จริงหน้า 2–11, ทำรายการเอกสาร ชื่อไฟล์ ภาษา วันหมดอายุ และลิงก์รูปเต็มก่อนนำเข้า
3. **แก้เนื้อหาขาด/เกิน:** Related Links และ Business ก่อน — ต้องอนุมัติการนำข้อความใหม่ออกหรือเก็บไว้ แล้วค่อยคืนรูป
4. **ยืนยันคำแปล:** หน้าแรกจีน, บทความธุรกิจ, Links, Contact, footer และเอกสารนโยบายญี่ปุ่น/จีน โดยอ้างเฉพาะข้อความที่ได้รับอนุมัติ
5. **ยืนยัน Contact Feedback:** เลือกบริการรับข้อความ/อีเมลและข้อกำหนดความเป็นส่วนตัว ถ้าจะคืนฟอร์ม; ห้ามจำลองผลส่งสำเร็จ
6. **แก้โครงข้อมูล:** ลดข้อมูลซ้ำระหว่าง `site.json` กับรายภาษา; จัด headings และ redirect แยกจากการเปลี่ยนเนื้อหา
7. **ตรวจรับหลังแก้:** เทียบครบ 28 หน้าใน desktop/mobile รวมภาพ ลิงก์ คำแปล ฟอร์ม และรายการเอกสาร; แนบหลักฐานหน้าต้นฉบับ/หน้าใหม่เป็นคู่ต่อหน้า ไม่ใช้ unit test ผ่านแทนการรับรองว่าข้อมูลตรง

**รอบนี้ยังไม่ได้ทำข้อแก้ไขเหล่านี้** เอกสารนี้เป็นรายการตรวจและข้อเสนอเพื่อให้อนุมัติก่อนลงมือ
