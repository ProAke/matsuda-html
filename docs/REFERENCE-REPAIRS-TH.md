# ซ่อม Static HTML เทียบกับเว็บอ้างอิง

> บันทึกการซ่อมรอบก่อน ดู `ALL-PAGES-LAYOUT-TH.md` สำหรับการตรวจครบ 29 หน้าและผลทดสอบล่าสุด

วันที่ 4 พฤศจิกายน 2026 — สาขา `arena/e5eaf122-matsuda-html`

อ้างอิงหลัก: https://hi.matsuda-sangyothailand.com/

## หลักฐานที่ตรวจได้

อ่านเนื้อหาหน้าแรกและหน้า `company.php`, `management.php`, `business.php`, `awarded.php`, `career.php` และ stylesheet `template/styles/template.css` ของเว็บจริงผ่านเครื่องมือ fetch ส่วน `contactus.php` ดึงเนื้อหา Google Maps เป็นหลัก จึงยังไม่ถือว่าเทียบเนื้อหาหน้าติดต่อครบถ้วน

CSS เว็บจริงยืนยันสี ขนาด wrapper 1024/920 px, ฟอนต์ดั้งเดิม, คอลัมน์, แกลเลอรี padding 60 px, ปุ่ม 44×44 และปุ่มสไลด์หน้าแรก 63×64 px หน้า Our Business มีภาพ `img-business1_en.png` และ `business_en.png` ส่วนหน้าแรกมีหัวข้อ “For Prosperity And A Beautiful Earth” ตามด้วย process graphics และส่วน Precious Metals Related Business

การเชื่อมต่อเว็บจริงโดยตรงจาก sandbox/Chromium ถูกจำกัด จึง **ไม่ได้ทำ screenshot/pixel-diff กับ live site และไม่อ้างว่าตรงทุกพิกเซล** ผล browser checks เป็นการทดสอบเว็บ local เท่านั้น เนื้อหาภาษา JP/TH/CN ใช้ไฟล์ static ที่มีอยู่ ไม่ได้อ้างว่าเทียบกับเว็บจริงครบ 21 หน้าภาษาต่างประเทศ

## สิ่งที่ซ่อม

- เอา hero banners ที่เพิ่มเข้ามาในชุด Drive และ inline margin `-350px` ออกจาก HTML ทั้ง 29 หน้า กลับไปใช้ลำดับเนื้อหาเดิม ไม่เพิ่มแบนเนอร์ใหม่
- คืนหัวข้อหน้าแรก EN และหัวข้อ Corporate Introduction หน้า Company EN ให้ตรงกับเนื้อหาที่ดึงได้จากเว็บจริง เพิ่มชื่อบริษัทในคอลัมน์แนะนำบริษัท
- ซ่อนบล็อก COMPANY PROFILE ที่มีแต่หัวข้อซ้ำและไม่มีข้อมูล เก็บ IDs ไว้ให้ resize script เดิมไม่พัง ตารางข้อมูลบริษัทเดิมยังอยู่ครบ
- คืนภาพหลักสองภาพใน Our Business ทั้ง 5 ไฟล์ เอาข้อความรายการธุรกิจที่ไม่ปรากฏในหน้าอ้างอิงออก ใช้ภาพต้นฉบับจาก Drive ไม่สร้างหรือออกแบบภาพใหม่
- ซ่อมเมนู desktop/mobile/footer และ logo ให้ไป section ที่ถูกต้องในภาษาปัจจุบัน รวมกรณีพิเศษ `management.html` = TH และ `management_en.html` = EN
- ซ่อมตัวเลือกภาษาที่เคย highlight ENG ทุกหน้าให้แสดงภาษาปัจจุบัน
- เพิ่มปุ่มเมนูมือถือที่ใช้ keyboard ได้ เปิด/ปิดและกด Escape ได้ โดยคงสีและรูปแบบของ template เดิม
- คืนขนาดและระยะปุ่มสไลด์ตาม CSS เว็บจริง แก้การคำนวณ `options.height` ใน `js/slider.js` ที่ใช้ width ผิดตัว
- คืนชื่อ font-family CordiaUPC ให้ใช้ไฟล์ WOFF ที่มีอยู่จริง ไม่พึ่งว่าคอมพิวเตอร์ผู้ใช้จะติดตั้งฟอนต์ไว้แล้ว
- แก้ตารางบริษัท รูปภาพ ฟอร์ม และคอลัมน์ footer ที่ล้นจอบนมือถือ โดยไม่ซ่อนปัญหาด้วย `overflow-x:hidden`
- ลบข้อมูลที่อยู่ซ้ำใน footer โดยเก็บสำเนาสุดท้ายที่มีชื่อบริษัทและข้อมูลครบ พร้อมทำชื่อบริษัทใน footer EN ให้เป็นภาษาอังกฤษ
- คืน class ของ thumbnail ใบรับรองให้จัดวางตาม template พร้อมแกลเลอรี dialog สำหรับใบรับรอง 6 รูปและแผนที่ติดต่อ มีปุ่มก่อนหน้า/ถัดไป/ปิดและ keyboard controls เก็บลิงก์ไฟล์ภาพจริงไว้สำหรับเปิดแท็บใหม่
- ใส่ alt ให้ภาพใบรับรองและแผนที่จาก title เดิม ไม่เดาเนื้อหาเอกสาร

แก้หลักใน HTML โดยตรง, `template/styles/reference-repairs.css`, `js/static-compat.js`, `js/slider.js` — ยังคงเป็น static HTML/CSS/JS ไม่มี Nuxt/Vue/JSON content renderer หรือ build step

`docs/source-manifest.json` ยังคงเป็น baseline ก่อนซ่อม ไม่เขียน hash ทับเพื่อปกปิดการแก้ไข asset ที่ตั้งใจแก้ในรอบนี้คือ `js/slider.js`; tests ยกเว้น hash ของไฟล์นี้โดยเจาะจงและตรวจสูตร height ที่ถูกต้องแทน รูปภาพและฟอนต์ต้นฉบับไม่เปลี่ยน

## ผลตรวจ

- `npm test`: **38/38 ผ่าน** ครอบคลุม HTTP, assets, inline JS, nav แยกภาษา, ลบแบนเนอร์แทรก, ภาพธุรกิจครบ, แกลเลอรี 6 เอกสาร และสูตรสไลด์
- Chromium เปิด **29 หน้า × 3 viewport (390/768/1280 px) = 87 ครั้ง** ไม่พบ page JS errors, local HTTP errors หรือภาพโหลดไม่สำเร็จในรอบตรวจ
- ไม่พบ horizontal overflow ทั้ง 87 กรณีที่ตรวจ ไม่ได้ใส่ `overflow-x:hidden` เพื่อทำให้ผลตรวจผ่าน
- ตรวจคลิกเมนูมือถือภาษาไทยไป Company TH, เปิดแกลเลอรีใบรับรอง, ปุ่ม ArrowRight และ Escape ผ่าน
- ทดสอบสไลด์ทั้งสอง, เลือกภาษา EN→TH และฟอร์มติดต่อทั้ง 4 ภาษาอีกรอบผ่าน ฟอร์มไม่ POST และไม่อ้างว่าส่งข้อความสำเร็จ
- รายละเอียด browser geometry และ interaction checks: `reference-browser-checks.json`
- พรีวิวใช้ `npm start` ที่พอร์ต **3000**, ไม่มีการใช้ cache/build จาก Nuxt

## ข้อจำกัดที่ยังต้องยืนยัน

1. ฟอร์มติดต่อไม่มี PHP/mail backend จึงยังส่งข้อความไม่ได้ มีคำเตือนชัดเจนตามเดิม
2. ปลายทาง Google Maps และ external links ต้องตรวจบนเครือข่ายผู้ใช้จริง ใน sandbox แผนที่อาจเป็นพื้นที่ว่างเพราะเชื่อมต่อภายนอกไม่ได้ ไม่ได้แทนด้วยแผนที่ปลอม
3. หน้า awards ของเว็บจริงระบุ “Page 1 from 11” แต่มีเพียง 6 เอกสารที่ตรวจยืนยันได้ และ source static มีเพียงหน้าเดียว จึงคง 6 เอกสาร/1 หน้า ไม่สร้างเอกสารหรือหน้า 2–11 ขึ้นเอง
4. ที่อยู่อีเมลที่แสดงกับ mailto บางรายการต่างกันมาตั้งแต่ต้นฉบับ ต้องให้ผู้รับผิดชอบยืนยันก่อนแก้ปลายทาง
5. ยังไม่ได้รับรองคำแปลทั้งหมดหรือความถูกต้องทางธุรกิจของทุกหน้า และไม่มีหลักฐาน screenshot live สำหรับยืนยัน pixel-perfect
6. JS libraries เก่ายังมาจากต้นฉบับ ควรตรวจ security/accessibility แยกก่อน production

เอกสารนำเข้าครั้งแรก `STATIC-IMPORT-TH.md` และรายงานใน `report/` เป็นบันทึกก่อนการซ่อมรอบนี้ ไม่ใช่สถานะปัจจุบัน
